# 화력 피부 맞춤 경험 개선 기획서

- 작성일: 2026-08-20
- 상태: 1차 핵심 구현 완료
- 대상: 홈, 피부 체크, 제품 탐색, 랭킹, 제품 상세, 비교, 마이화력
- 핵심 목표: 사용자가 “내 피부에 무엇이 맞는가?”라는 질문에 빠르게 답을 얻고, 그 답을 신뢰하며 다음 행동까지 이어가게 한다.

## 0. 구현 현황 — 2026-08-20

이번 구현에서 서비스의 우선 기준을 `마케팅·인지도`가 아니라 `성분 근거와 내 피부 적합성`으로 변경했다.

### 완료

- 비회원도 사용할 수 있는 6단계 `1분 피부 체크`와 맞춤 제품 3개 결과 화면
- 체크 결과를 브라우저에 보관하고 로그인 후 상세 프로필 확인·저장으로 이어지는 흐름
- 성분 구성 55%, 피부 적합 35%, 데이터 신뢰 10%의 공통 추천 엔진
- 광고비, 판매량, 브랜드 인지도, 기존 관리자 점수를 랭킹 계산에서 제외
- 성분 자료가 없는 제품은 42점·낮은 신뢰도로 보수적으로 표시
- 신생 브랜드도 같은 성분·근거 기준으로 평가하고, 동점이면 성분 점수와 데이터 신뢰를 보조 정렬 기준으로 사용
- 피부 타입, 수분·유분, 민감도, 트러블 빈도·위치, 세안 후 당김, 붉은기, 모공, 제형, 루틴 단계, 선케어 습관, 반응 성분, 환경, 면도·메이크업·이중 세안 맥락을 추천 이유 또는 주의 안내에 연결
- 제품 목록의 피부 고민, 가격, 성분 자료 신뢰 필터와 성분 구성 정렬을 실제 동작하도록 구현
- 홈, 제품 카드, 랭킹, 상세, 비교, 원칙 화면에 점수 근거·추천 이유·신뢰도·브랜드 중립 원칙 표시
- 면도와 메이크업을 성별 대신 실제 생활 습관 선택지로 추가
- 모바일 제품 목록에서 상세 진입 시 화면 중간 위치가 유지되던 문제 수정

### 부분 완료·다음 단계

- 현재 제품 DB에 용량, 향, 실제 제형, 아침·저녁 사용 단계, 메이크업 밀림 데이터가 없어 해당 필터와 루틴 조합은 다음 스키마 확장 때 구현한다.
- 연결된 성분은 전체 INCI가 아닌 등록된 주요 성분 기준이다. 전성분 수집이 늘수록 반응 성분 경고와 신뢰도가 정교해진다.
- 선호 성분은 성분 상세와 마이페이지에 저장되지만 전체 제품 랭킹 가중치에는 아직 합치지 않았다.
- 목적·카테고리별 랭킹, 아침·저녁 루틴 빌더, 계절별 재체크, 추천 변화 이력, 분석 이벤트 대시보드는 후속 범위다.

## 1. 결론

화력은 이미 상세한 피부 프로필, 제품별 적합도, 성분·리뷰·비교 화면을 갖추고 있다. 현재 가장 큰 문제는 기능의 수가 아니라 **입력한 정보와 추천 결과 사이의 연결이 사용자에게 충분히 보이지 않는 것**이다.

우선 해결할 문제는 다음 다섯 가지다.

1. 피부 체크를 체험하려면 로그인부터 해야 하고, 10단계를 모두 지나야 해서 첫 가치 경험이 늦다.
2. 사용자가 입력한 정보 중 상당수가 랭킹 또는 상세 적합도에 반영되지 않는다.
3. 서로 다른 피부 조건에서도 100점과 1등급이 반복되어 추천 차이가 약하게 느껴진다.
4. 면도, 수염 부위, 메이크업, 클렌징 습관, 현재 사용 성분 같은 실제 생활 맥락이 빠져 있다.
5. 추천 결과가 “무엇을 먼저 사고, 어떻게 루틴에 넣을지”까지 이어지지 않는다.

개선 방향은 남성용·여성용 추천을 따로 만드는 것이 아니다. 성별을 점수의 직접 변수로 사용하지 않고, **면도·메이크업·루틴·환경처럼 피부에 실제로 영향을 주는 행동을 선택형으로 받는 방식**이 적절하다.

## 2. 점검 방법

### 점검 환경

- 데스크톱: 1440 × 900
- 모바일: 390 × 844
- 실제 확인 경로: 홈 → 피부 프로필 → 랭킹 → 제품 탐색 → 제품 상세 → 비교
- 피부 체크는 기존 사용자 정보를 덮어쓰지 않도록 결과 확인 단계까지만 진행하고 저장하지 않았다.
- 추천 로직은 같은 제품에 두 개의 가상 피부 조건을 적용하는 미리보기 API로 추가 확인했다.

### 가상 사용자 A — 남성 초보 사용자

- 29세, 스킨케어 지식이 많지 않음
- 겉 유분과 속당김이 함께 있음
- 면도 후 턱과 입가가 붉어지고 트러블이 생김
- 1~2단계의 간단한 루틴과 산뜻한 제형 선호
- 선크림을 자주 바르지 않음
- 기대: “세안 후 뭘 하나 바르면 되는지, 면도 후 무엇이 덜 자극적인지” 빠르게 알고 싶음

### 가상 사용자 B — 여성 숙련 사용자

- 34세, 세럼과 크림을 포함한 여러 단계 루틴 사용
- 속건조와 민감, 주기적으로 생기는 턱 트러블이 있음
- 메이크업 밀림, 붉은기, 칙칙함과 탄력이 고민
- 향료와 고기능성 성분 조합에 신중함
- 기대: “현재 루틴과 겹치지 않으면서 메이크업 전에 쓰기 좋은 제품”을 찾고 싶음

## 4. 확인된 구조적 문제

### 4.1 입력 정보와 추천 로직의 불일치 — P0

피부 프로필은 10단계에서 다양한 정보를 받지만 랭킹은 피부 타입, 수분, 유분, 민감도, 선호 제형과 일부 고민만 사용한다.

- 랭킹에서 사용하지 않는 주요 정보: 트러블 빈도와 위치, 세안 후 당김, 붉어짐 빈도, 모공 체감, 루틴 단계, 선케어 습관, 반응 유발 요인, 생활 환경
- 제품 상세 분석에서 직접 활용되지 않는 정보: 모공 체감, 트러블 위치, 선호 성분
- 랭킹에서 실제 가점에 사용하는 고민은 피부 장벽과 붉은기 중심이다.
- 상세 점수에서 직접 사용하는 고민은 속건조, 민감, 피부 장벽, 붉은기이며 모공, 각질, 칙칙함, 탄력은 점수에 영향을 주지 않는다.

사용자는 모든 질문이 추천에 반영된다고 기대한다. 이 불일치는 추천 신뢰를 크게 떨어뜨릴 수 있다.

**원칙:** 저장하는 모든 항목은 눈에 보이는 출력으로 연결하거나, 결과에 사용하지 않는 참고 정보임을 명확히 표시해야 한다.

### 4.2 점수 포화와 근거 약화 — P0

두 가상 프로필로 같은 토너를 분석했을 때 모두 100점, 1등급, “매우 잘 맞아요” 결과가 나왔다.

- 남성 가상 조건: 지성, 수분 부족, 높은 유분·민감도, 잦은 트러블, 산뜻한 제형 선호
- 여성 가상 조건: 민감, 수분·유분 부족, 높은 민감도, 오래가는 당김, 리치한 제형 선호

두 조건의 세부 부담 수치는 달랐지만 최종 점수와 판정은 같았다. 전체 랭킹에서도 두 시나리오 모두 상위 3개가 100점이었다.

현재 세부 보습력·진정력·장벽 점수가 종합 적합도에 일정 값을 더하거나 빼는 방식이라 서로 독립적인 근거처럼 보이기 어렵다. 또한 제품의 효능 문구에 특정 키워드가 있는지로 가점을 주기 때문에 “성분과 사용감을 정밀하게 분석한다”는 화면 기대와 실제 계산 사이에 차이가 있다.

### 4.3 첫 가치 경험이 늦음 — P0

홈의 “내 피부 프로필 만들기”는 로그인된 사용자에게는 잘 작동하지만, 신규 사용자는 회원가입 후 10단계를 마쳐야 개인화 결과를 볼 수 있다. 피부가 맞는지 궁금해서 들어온 사용자에게 계정 생성은 너무 이른 요구다.

### 4.4 성별이 아니라 생활 맥락이 부족함 — P1

남녀로 추천 제품을 나누는 것은 피부 적합성의 근거가 약하고 고정관념을 만들 수 있다. 대신 다음 맥락을 선택형 모듈로 받아야 한다.

- 면도 여부, 빈도, 면도 후 따가움·붉어짐, 수염이 나는 부위
- 메이크업 빈도, 유지 시간, 베이스 밀림, 사용하는 클렌징 방식
- 현재 사용하는 고기능성 성분과 같은 날 겹쳐 쓰는 제품
- 주기적으로 반복되는 트러블 패턴
- 임신·수유 또는 피부 치료 중 안전 정보가 필요한지 여부 — 선택 항목이며 전문 진료를 대체하지 않음
- 향, 마무리감, 예산, 루틴에 추가 가능한 단계

### 4.5 탐색과 결과가 행동으로 이어지지 않음 — P1

현재 랭킹은 여러 카테고리를 한 줄로 세우고, 상세는 정보가 풍부하지만 “오늘 내 루틴에서 무엇을 바꾸면 되는가”에 답하지 않는다. 사용자는 최고 점수보다 다음과 같은 답을 원한다.

- 세안제, 보습제, 선케어 중 무엇을 먼저 바꿀지
- 아침과 저녁 중 언제 사용할지
- 현재 제품과 같이 써도 되는지
- 면도 직후나 메이크업 전에 사용해도 되는지
- 가격과 용량을 고려하면 어떤 제품이 현실적인지

## 5. 개선 목표와 지표

분석 도구가 연결된 뒤 아래 이벤트를 기준선부터 수집한다. 수치는 1차 가설이며 2주간의 실제 데이터로 조정한다.

| 목표 | 핵심 지표 | 1차 목표 |
| --- | --- | --- |
| 빠른 가치 경험 | 홈 방문 → 빠른 피부 체크 시작률 | 35% 이상 |
| 피부 체크 완주 | 빠른 체크 시작 → 결과 확인률 | 70% 이상 |
| 추천 이해 | 결과 화면에서 ‘왜 맞는지’ 확인률 | 40% 이상 |
| 탐색 전환 | 결과 → 제품 상세 진입률 | 45% 이상 |
| 비교·저장 전환 | 결과 → 찜 또는 비교 실행률 | 20% 이상 |
| 프로필 고도화 | 빠른 체크 완료자 → 정밀 체크 전환률 | 25% 이상 |
| 추천 구분력 | 상위 6개에서 동일 점수로만 정렬되는 세션 | 10% 이하 |

## 6. 목표 사용자 흐름

```text
홈
  → 1분 피부 체크
    → 6개 핵심 질문
      → 로그인 전 결과 미리보기
        → 피부 상태 요약 + 가장 먼저 바꿀 루틴 1개
          → 제품 후보 3개 + 각 추천 이유
            → 저장할 때 회원가입
              → 선택형 정밀 체크
                → 맞춤 탐색·상세·비교·마이루틴
```

핵심 변화는 **회원가입 전에 결과를 보여주고, 정밀 체크는 결과를 더 좋아지게 만드는 선택 사항으로 바꾸는 것**이다.

## 7. 기능 요구사항

### 7.1 홈과 첫 진입

#### UX-01. 빠른 피부 체크 CTA — P0

- 주 CTA를 `1분 피부 체크`로 변경한다.
- 보조 CTA는 `제품부터 둘러보기`로 둔다.
- CTA 아래에 `가입 없이 결과 확인 · 저장할 때 로그인`을 표시한다.
- 결과 미리보기에는 피부 요약, 추천 이유, 제품 3개가 실제 형태로 보여야 한다.

#### UX-02. 성별 중립 비주얼 확장 — P1

- 현재 매화와 로즈 컬러는 브랜드 자산으로 유지한다.
- 제품 탐색·분석 화면에는 샌드, 세이지, 네이비 계열의 중립 보조 테마를 추가한다.
- 인물 이미지를 사용할 경우 성별, 연령, 피부 톤이 한쪽으로 치우치지 않게 구성한다.
- `남성용`, `여성용` 진입 버튼은 만들지 않는다.

### 7.2 피부 체크

#### UX-03. 빠른 체크와 정밀 체크 분리 — P0

빠른 체크는 6개 질문, 목표 완료 시간은 60~90초다.

1. 세안 후 피부 변화: 수분과 유분
2. 붉어짐·따가움: 민감 반응
3. 트러블 빈도와 대표 위치
4. 가장 바꾸고 싶은 고민 최대 3개
5. 선호 사용감
6. 현재 루틴 복잡도와 먼저 찾을 제품군

정밀 체크는 아래 선택형 모듈로 제공한다.

- 면도와 수염 부위
- 메이크업과 클렌징
- 생활 환경과 계절
- 현재 사용하는 고기능성 성분
- 반응 유발 성분과 피하고 싶은 사용감
- 예산과 선호 루틴 단계

#### UX-04. 고민 항목 재구성 — P0

현재 고민을 다음처럼 사용자가 찾는 표현으로 확장한다.

- 속건조·당김
- 유분·번들거림
- 트러블·여드름
- 블랙헤드·모공
- 붉은기·민감
- 장벽·각질
- 잡티·칙칙함
- 탄력·잔주름

모든 고민은 랭킹, 상세 분석 또는 안전 안내 중 적어도 한 곳에 실제 반영되어야 한다.

#### UX-05. 진행 보존과 설명 — P1

- 로그인 전 답변은 브라우저 세션에 임시 저장한다.
- 새로고침 또는 로그인 왕복 후에도 이어서 작성할 수 있어야 한다.
- 현재 단계뿐 아니라 예상 남은 시간을 보여준다.
- 질문마다 `추천에 이렇게 사용돼요`를 유지하되 실제 사용 화면을 링크한다.
- `모르겠어요`를 모든 전문 용어 질문에 제공한다.

### 7.3 결과 화면

#### UX-06. 체크 완료 직후 맞춤 결과 — P0

결과 화면의 첫 화면에는 아래 다섯 요소를 배치한다.

1. `현재 피부 스냅샷` — 진단 표현을 피하고 최근 관찰 결과임을 표시
2. `가장 먼저 챙길 것` — 1순위 피부 목표
3. `첫 루틴 제안` — 세안·보습·선케어 중 우선 한 단계
4. `제품 후보 3개` — 같은 제품군 안에서 추천
5. `왜 맞는지` — 입력값과 제품 근거를 연결한 문장 2~3개

추천 이유 예시:

- `면도 후 붉어짐을 선택해 향료가 없고 진정 근거가 있는 제품을 먼저 보여드려요.`
- `메이크업 전 사용을 선택해 밀림 리뷰가 적고 흡수가 빠른 제형을 우선했어요.`
- `1~2단계 루틴을 선호해 여러 기능을 한 번에 채우는 보습제를 골랐어요.`

### 7.4 랭킹과 점수

#### UX-07. 점수 체계 분리 — P0

하나의 100점에 모든 의미를 넣지 않고 아래 세 축을 분리한다.

- `피부 궁합`: 사용자가 입력한 조건과 제품 특성의 적합도
- `정보 신뢰도`: 성분 출처, 리뷰 수, 최근 확인일의 충분함
- `실사용 만족`: 피부 유형과 사용 기간이 비슷한 리뷰의 결과

개인화 가점은 점수 상한에 단순히 더하지 않고 정규화한다. 동일 점수는 공동 순위로 표시하고, 보조 정렬 기준을 화면에 공개한다.

#### UX-08. 루틴 슬롯별 랭킹 — P1

- 전체 순위 대신 `클렌저`, `수분 보충`, `보습`, `선케어`, `집중 케어`로 나눈다.
- 각 1위 카드에 `왜 이 제품이 1위인지`를 2개 태그로 표시한다.
- 상위 제품이 같아도 사용자별 추천 이유와 주의점은 달라야 한다.

### 7.5 제품 탐색과 상세

#### UX-09. 실제 동작하는 맞춤 필터 — P1

데스크톱의 ‘연동 예정’ 칩을 실제 필터로 전환하고 모바일에도 같은 기능을 제공한다.

- 내 피부 궁합 80점 이상
- 피부 고민
- 사용감과 마무리
- 향 유무
- 가격 범위
- 루틴 단계
- 정보 신뢰도
- 카테고리

프로필이 있으면 기본 정렬을 `내 피부 궁합 순`으로 하고, `기본 화력 순`과 명확히 구분한다.

#### UX-10. 상세 상단 요약 개선 — P1

- 기본 화력점수와 개인 적합도를 다른 색과 라벨로 분리한다.
- `나에게 맞는 이유`, `확인할 점`, `추천 사용 순서`를 첫 화면에 배치한다.
- 특정 반응 성분을 선택했다면 실제 전성분과 대조한 결과를 보여준다.
- 반응 성분이 제품에 없으면 `선택한 주의 성분은 확인되지 않았어요`라고 표시한다.
- 성분 출처, 확인일, 리뷰 수, 정보 신뢰도를 함께 제공한다.
- `토너 제형 고민을 함께 챙길 수 있어요`처럼 제품 보조 문구를 고민으로 잘못 해석하는 문장을 제거한다.

### 7.6 비교와 마이화력

#### UX-11. 목적 중심 비교 — P1

- 기본 비교는 같은 카테고리 제품끼리 제안한다.
- 다른 카테고리를 비교하면 `역할이 다른 제품`임을 먼저 표시한다.
- 가격, 용량, 10ml당 가격, 제형, 마무리, 향, 리뷰 신뢰도를 추가한다.
- 모바일에서는 가로 표 외에 `제품 A / 제품 B 카드 전환` 보기를 제공한다.
- 결과는 `더 높은 점수`보다 `누구에게 어떤 상황에서 더 적합한지`로 설명한다.

#### UX-12. 마이화력을 ‘내 루틴’ 중심으로 재배치 — P2

- 상단에 아침·저녁 루틴과 비어 있는 단계를 먼저 보여준다.
- 맞춤 추천을 최근 본 기록보다 위로 이동한다.
- 최근 본 제품은 부가 정보로 접는다.
- 계절 변화 또는 프로필 수정 후 `다시 체크할까요?`를 안내한다.

## 9. 카피 원칙

- `남성 피부`, `여성 피부`보다 `면도 후`, `메이크업 전`, `간단한 루틴`처럼 상황을 말한다.
- `진단`, `효과 보장`, `완벽히 맞음`을 사용하지 않는다.
- 점수보다 이유를 먼저 말한다.
- 전문 용어에는 짧은 생활 표현을 함께 제공한다.
- 입력하지 않은 정보로 사용자를 추정하지 않는다.

권장 문구:

- `1분만에 지금 피부를 가볍게 체크해 보세요.`
- `가입 없이 결과를 보고, 저장할 때 로그인하세요.`
- `면도 후 턱과 입가가 따갑거나 붉어지나요?`
- `메이크업을 하는 날, 제품이 밀리거나 들뜨는 편인가요?`
- `이 제품이 잘 맞는 이유 3가지`
- `현재 정보로는 확신이 낮아요. 리뷰가 더 모이면 다시 알려드릴게요.`

## 11. 완료 조건

### 기능

- 비회원이 빠른 체크를 완료하고 결과와 제품 3개를 볼 수 있다.
- 저장 또는 찜을 시도하는 시점에만 로그인을 요청한다.
- 새로고침과 로그인 왕복 후에도 체크 진행 상태가 복원된다.
- 모든 프로필 입력값은 랭킹, 상세, 사용 안내, 주의 안내 중 한 곳에 연결된다.
- 사용하지 않는 값은 저장 전에 `추천 점수에는 사용하지 않음`으로 표시한다.
- 같은 점수는 공동 순위 또는 공개된 보조 기준으로 정렬한다.
- 개인 점수와 기본 점수의 차이를 한 문장으로 설명할 수 있다.
- 반응 성분 경고는 실제 전성분과 대조해 일치 여부를 표시한다.

### 사용자 경험

- 빠른 체크는 모바일에서 90초 안에 완료할 수 있다.
- 필수 질문은 한 화면에 핵심 선택 1~2개만 둔다.
- 모바일 하단 내비게이션이 다음·저장 버튼과 결과를 가리지 않는다.
- 제품 카드에서 `왜 나에게 맞는지`를 상세 진입 전 확인할 수 있다.
- 비교 화면에서 같은 카테고리와 다른 카테고리를 명확히 구분한다.
- 색상만으로 점수, 상태, 선택 여부를 전달하지 않는다.

### 추천 품질

- 서로 반대되는 피부 조건을 넣었을 때 상위 제품 또는 추천 이유가 의미 있게 달라진다.
- 상위 제품이 같다면 조건별 사용법과 주의점이 달라진다.
- 모공, 각질, 칙칙함, 탄력 등 제공하는 모든 고민이 계산 또는 설명에 실제 반영된다.
- 정보가 부족한 제품은 높은 적합도보다 신뢰도 부족을 먼저 표시한다.

## 12. 이번 기획에서 하지 않는 것

- 성별만으로 제품 점수를 다르게 계산하지 않는다.
- 피부 질환을 진단하거나 치료법을 추천하지 않는다.
- 데이터 근거가 없는 상태에서 AI 문장만으로 정밀함을 연출하지 않는다.
- 제품 수를 늘리는 것만으로 추천 품질 문제를 해결하려 하지 않는다.

## 13. 최종 권고

첫 구현 순서는 `빠른 체크 → 결과 미리보기 → 점수 근거 정비 → 실제 맞춤 필터`가 적절하다. 생활 맥락 문항과 마이루틴은 그다음이다.

화력의 강점은 질문 수가 많다는 데 있지 않다. 사용자가 남긴 작은 관찰 하나가 추천 이유와 주의 안내로 정확히 되돌아올 때 서비스의 신뢰가 생긴다.
