# 마이화력 개인 대시보드와 사진 피부 관찰

## 방향

메인은 제품 발견, 마이페이지는 개인 기록 정리에 집중한다. 흰 배경과 연분홍 포인트, 작은 정보 카드와 세로 목록을 사용한다. 그라데이션·제품 이미지·중복 추천 진열을 제거한다.

## 화면 구성

- `/my`: 닉네임과 프로필 설정 → 내 기록/사진 피부 분석 메뉴 → 리뷰·화력·찜·비교 수치 → 답변 기반 피부 요약 → 사진 분석 진입 → 관심 성분 → 활동 → 찜·비교·최근 본 텍스트 목록 → 설정.
- 목록은 처음 3개, 나머지는 펼치기. 찜 해제와 저장된 비교 순서 복원, 영상 관리 등 기존 기능을 유지한다.
- 미등록 정보는 ‘미등록’, 조회 실패는 ‘불러오지 못함’, 실제 0은 0으로 구분한다. 임의 피부 타입으로 추천을 만들지 않는다.
- `/my/photo-analysis`: 촬영 안내 → 카메라/앨범 → 기기 내 미리보기 → 외부 전송 동의 → GPT 관찰 → 부위별 특징·불확실성·일반 관리 습관.
- 흐리거나 적합하지 않은 사진은 재촬영 안내만 제공한다. 사진 분석으로 저장된 피부 프로필이나 랭킹을 자동 변경하지 않는다.

## API와 운영 설정

`backend/.env`에 아래 서버 전용 설정을 추가하고 백엔드를 재시작한다. 키는 채팅·Git·프론트엔드·NEXT_PUBLIC 환경 변수에 넣지 않는다.

```dotenv
OPENAI_API_KEY=실제_API_키
OPENAI_SKIN_PHOTO_ENABLED=true
OPENAI_SKIN_PHOTO_MODEL=gpt-4.1-mini
OPENAI_SKIN_PHOTO_DAILY_LIMIT=3
```

OpenAI 프로젝트 결제와 모델 접근 권한이 필요하다. 기본은 비활성화다. 키만 등록해도 enabled를 켜기 전에는 유료 요청하지 않는다. 프로젝트 사용량 알림과 지출 정책을 운영자가 별도로 설정한다.

- GET `/api/v1/users/me/photo-analysis`: 사용 가능 여부·하루 한도·남은 횟수.
- POST 같은 경로: 로그인 JWT + `X-Photo-Consent: photo-v1`, image/jpeg 또는 image/png 원시 본문. 사용자 지정 외부 이미지 URL은 받지 않는다.
- Next Server Action에서 로그인·동의·파일 검사, 백엔드에서 다시 활성 계정·동의·실제 이미지 형식·해상도를 검사한다.
- JPEG/PNG 5MB, 최소 256×256, 최대 2천만 화소. 브라우저에서 방향을 적용하고 최대 변 1024px로 축소, 백엔드에서도 재인코딩해 메타데이터를 제거한다.
- 백엔드는 multipart 임시 파일 대신 최대 크기가 제한된 원시 입력과 ImageIO 메모리 스트림을 사용한다.
- Responses API, 이미지 입력, 엄격한 JSON 스키마, `store:false`, 45초 제한, 자동 재시도 없음. 인증 키·이미지·모델 응답은 로그에 출력하지 않는다.
- V32 마이그레이션은 사용자별 하루 요청 수와 마지막 요청 시각만 저장한다. 사용자 행 잠금으로 동시 요청을 제어하고 60초 간격·하루 기본 3회(설정 범위 1~10회)를 적용한다. 비용이 발생했을 가능성이 있는 API 오류와 재촬영 결과도 횟수에 포함한다. 계정 삭제 시 사용량 행도 삭제한다.

## 관찰 범위와 개인정보

사진 분석은 피부 표면의 보이는 특징을 정리하는 참고 기능이다. 의료 진단, 질병 유무, 나이·인종·감정·신원, 실제 수분/유분 수치, 영구 피부 타입, 성분 적합성을 추정하지 않도록 지시한다. 점수·질환명·처방 기능은 제공하지 않는다. 조명·화장·보정에 따른 오차와 모델 오류를 항상 안내한다. 의료 증상 평가 도구로 홍보하지 않는다.

본인 사진 전송에 매번 명시적으로 동의해야 한다. 선택/미리보기만으로 전송하지 않는다. OpenAI에 이름·이메일·계정 식별자·피부 프로필을 보내지 않는다. 화력은 사진과 분석 결과를 DB·파일·localStorage 등에 영구 저장하지 않는다. 결과는 현재 화면 메모리에만 유지되며 사진·결과 지우기로 제거한다. OpenAI의 별도 보관과 화력의 비저장을 혼동하지 않도록 안내한다.

OpenAI API 데이터는 기본적으로 학습에 사용되지 않지만 악용 방지 로그 등이 최대 30일 또는 예외적으로 더 보관될 수 있다. `store:false`가 모든 보관을 0일로 만드는 것은 아니다. 실제 서비스 공개 전 운영자는 OpenAI 계약·처리 지역·국외 이전 고지 및 개인정보 처리 적합성을 별도로 검토해야 한다. 앱의 기술적 동의 UI만으로 모든 법적 요구가 충족됨을 보장하지 않는다.

## 검증 기준

- 프로필 등록/미등록/조회 실패, 실제 활동 수치, 제품 이미지 없음, 상세·찜·비교 연결.
- 사진 촬영/앨범, 동의 미체크, 잘못된 형식/크기, 분석 중 중복 방지, 키 미설정, API 오류/거절/재촬영/정상 결과.
- 백엔드 정상 이미지 재인코딩, 비이미지 거부, 동의/계정 보호, 하루 한도·일자 변경·쿨다운, 응답 형식 검증.
- 실제 얼굴 사진의 유료 API 호출은 운영자 키 설정과 사용자 동의 후 별도 확인한다. 자동 테스트는 합성 이미지와 모의 응답만 사용한다.

## 2026-09-10 구현 검증 기록

- 프론트엔드 테스트 39개 통과(새 대시보드·사진 입력·서버 동의 검사 6개 포함), 타입 검사 및 프로덕션 빌드 통과.
- 사진 백엔드 테스트 8개 통과: JPEG/PNG 재인코딩, 잘못된 사진, 키/기능 비활성화, 요청 구조, 결과/재촬영/오류 파싱, 동의, 하루 한도·쿨다운·한국 자정, 비활성 계정.
- PostgreSQL V32 적용 및 백엔드 재기동 완료. 상태 확인 UP. 로그인 없는 GET/POST 사진 API 모두 401.
- 실제 `/my` 비로그인 리다이렉트 확인. 개인정보·계정 변경 없이 실제 컴포넌트를 가상 데이터로 렌더링하여 390px 대시보드 및 360px 사진 화면의 가로 넘침 없음과 제품 이미지 없음 확인.
- 실제 API 키 미등록: 실제 얼굴 사진 전송·유료 GPT 호출은 수행하지 않음. 키 활성화 후 본인 사진 및 동의로 촬영/앨범→실제 결과 흐름을 최종 확인해야 함.
