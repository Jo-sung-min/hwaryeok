# 화력 커뮤니티: 사용법 영상과 리뷰어 랭킹

## 목적과 점수 분리

실제 제품 사용 경험을 모으는 원칙을 유지하면서, 좋은 리뷰를 쓴 사람과 사용법을 소개하는 크리에이터를 발견할 수 있게 한다.

- 제품 리뷰점수: 작성자가 제품에 매긴 항목별 점수. 기존 제품당 1인 1리뷰 정책을 유지한다.
- 리뷰 도움 평가: 다른 사용자가 특정 리뷰에 매기는 1~5점. 본인 리뷰는 평가할 수 없고, 리뷰별 1인 1평가로 수정·취소가 가능하다.
- 리뷰 화력: 받은 도움 평가를 이용한 리뷰어 활동 지표. 온도 모양으로 0~100 범위를 표현하지만 피부 건강, 제품 효능, 구매 인증 또는 신원 인증 지표가 아니다.
- 광고 추천점수: 기존 관리자의 제품 광고 추천점수. 위 두 사용자 평가 지표와 혼합하지 않는다.

## 사용자 동선

1. 제품 상세의 ‘영상으로 보는 사용법’에서 유튜브 영상과 자신의 채널을 등록한다.
2. 로그인 사용자는 제목·영상 주소·채널 이름·채널 주소·소개를 제출한다. 제출 즉시 `PENDING`이며 공개되지 않는다.
3. MY → 내 사용법 영상에서 검토 결과를 확인하고 수정·삭제한다. 승인 이후 수정도 다시 검토 대기로 전환된다.
4. 관리자가 승인한 영상만 제품 상세에 최대 3개 미리보기로 표시된다. 전체보기에서 페이지별로 더 볼 수 있다.
5. 공개 카드의 영상·채널 링크는 각각 유튜브로 이동한다. 사용자 제출 정보이며 채널 소유권 인증은 아니라는 점을 표시한다.
6. 제품 상세와 작성자 리뷰 목록에서 리뷰의 도움 정도를 평가한다.
7. ‘리뷰어 랭킹’에서 목록형 프로필을 탐색하고 피부타입을 필터링한다. 프로필을 선택하면 리뷰 화력, 평가자 수, 받은 평가 수, 제품에 매긴 평균 점수와 작성 리뷰를 확인한다.

## 관리자 운영

`/admin/usage-videos`에서 전체·대기·승인·반려·숨김을 조회한다.

- 승인(APPROVED): 영상과 채널의 연관성, 사용법 적합성, 광고/협찬 표시 등을 사람이 확인한 후 노출한다.
- 반려(REJECTED): 검토 메모로 수정 이유를 작성자에게 안내한다.
- 숨김(HIDDEN): 승인 이후에도 노출을 중단한다.
- 추천(featured)과 노출 순서(displayOrder): 추천 우선, 작은 순서값 우선, 최근 검토순으로 정렬한다.
- 검토 메모는 작성자와 관리자에게만 보이며 공개 응답에서는 제외한다.
- 승인 작업 자체가 영상 내용의 진실성·효능·채널 소유권을 자동 검증하지는 않는다.

## 리뷰어 집계 규칙

활성 계정이 공개 제품에 작성한 리뷰만 포함한다. 평가자도 활성 계정이어야 한다. 피부타입은 현재 저장한 피부 프로필만 공개하며 상세 피부 관찰 정보나 이메일을 공개하지 않는다.

동일 평가자가 한 작성자의 여러 리뷰에 평가했다면, 그 평가자의 점수를 먼저 평균낸다. 서로 다른 평가자들의 평균값을 다시 평균하여 `m`(1~5), 서로 다른 평가자 수를 `n`이라 한다.

`리뷰 화력 = round(50 + (m × 20 − 50) × n / (n + 5), 1)`

- `n = 0`이면 점수와 순위는 null, 화면은 ‘집계 전’. 임의의 기본 점수를 표시하지 않는다.
- 평가자가 적을 때 기준값 50으로 보정하여 소수 평가의 영향을 완화한다.
- 정렬: 리뷰 화력 내림차순 → 평가자 수 → 받은 평가 수 → 닉네임/ID로 일관된 순서.
- 평가 없는 작성자는 순위 없이 목록 뒤에 표시한다. 공개 리뷰가 없으면 랭킹 목록에 참여하지 않는다.
- 피부타입 필터의 순위는 필터 내 순위이고, 작성자 프로필의 순위는 전체 순위다.
- 단일 리뷰의 도움 평균은 그 리뷰에 받은 평가의 단순 평균이다. 작성자 프로필의 도움 평균은 평가자별로 정규화한 평균이다.
- 별도 계정을 이용한 조직적인 조작까지 자동 판별하는 시스템은 아니다. 이용자 규모가 커지면 신고·이상 패턴 탐지·평가 빈도 제한·운영 제재를 추가 검토한다.

## 데이터와 보안

- V29: 리뷰 도움 평가 테이블, 리뷰+평가자 복합 키, 1~5 범위. 동시 첫 투표도 중복 없이 처리한다.
- V30: 제품 사용법 영상 테이블, 등록자/제품/정규화 영상 ID 중복 방지, 검토 이력 필드.
- 영상/채널은 HTTPS 유튜브 허용 주소만 처리한다. 위장 도메인·계정정보 포함 URL·임의 포트·잘못된 영상 ID를 거절한다.
- 서버에서 임의 외부 URL을 가져오지 않는다. 유튜브 API 키나 자동 재생·임베드가 필요하지 않다.
- 등록·평가는 서버가 로그인 계정으로 소유자를 결정한다. 타인 수정·삭제, 자기 평가, 비활성 계정, 비공개 제품을 방어한다.
- 모든 관리자 API는 역할과 현재 계정 상태를 확인한다. 프론트 버튼을 숨기는 것에만 의존하지 않는다.

## 화면과 API

| 화면 | 용도 |
| --- | --- |
| `/reviewers` | 피부타입별 리뷰어 랭킹 |
| `/reviewers/{userId}` | 공개 프로필과 작성 리뷰, 도움 평가 |
| `/products/{id}#usage-videos` | 승인 영상 미리보기, 사용자 등록 |
| `/products/{id}/usage-videos` | 전체 승인 영상 |
| `/my/usage-videos` | 내 제출과 검토 상태 관리 |
| `/admin/usage-videos` | 관리자 노출 관리 |

주요 API는 `/api/v1` 아래에 위치한다.

- `GET/PUT/DELETE /reviews/{reviewId}/firepower`
- `GET /reviewers/ranking`, `GET /reviewers/{userId}/profile`
- `GET/POST /products/{productId}/usage-videos`
- `GET /me/usage-videos`, `PATCH/DELETE /me/usage-videos/{id}`
- `GET /admin/usage-videos`, `PATCH /admin/usage-videos/{id}`

검증은 별도 테스트 데이터베이스의 자동 테스트로 수행한다. 실제 사이트에 가짜 영상·사용자·평가를 적재하지 않는다.

## 구현 검증 (2026-09-07)

- 백엔드 전체 테스트 134개 통과 후, 추가 HTTP 권한 테스트 3개를 별도 실행하여 통과했다.
- 프론트 타입 검사와 배포 빌드 통과. 실제 PostgreSQL에 V29·V30 적용 후 정상 재시작을 확인했다.
- 실제 사이트의 랭킹·피부 필터·영상 전체보기·제품 상세 응답 확인. 실제 데이터가 없는 상태는 빈 목록으로 유지했다.
- 데스크톱 및 390px 모바일에서 빈 상태, 피부 필터, 사용법 바로가기, 합성 데이터 기반 리뷰어 목록→프로필→작성 리뷰, 승인 영상과 채널 카드 배치를 점검했다.
- 반복 시각 검증용 `frontend/tests/community-fixture-server.mjs`는 127.0.0.1:18080에서만 동작하는 읽기 전용 메모리 fixture다. 실제 DB 연결이나 외부 요청은 하지 않는다. 별도 프론트 테스트 프로세스의 `API_URL`에만 연결하며 일반 개발 환경의 `.env`에는 등록하지 않는다.
