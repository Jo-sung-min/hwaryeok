# 핵심 성분 공개 함량 기반 추천 계획 및 적용 결과

> 기준일: 2026-09-11  
> 적용 범위: 제품 상세, 성분별 랭킹, 개인 맞춤 추천, 관리자 제품 관리

## 1. 목표

화력은 제품마다 브랜드·제품 포장·식약처 보고·시험성적서에서 **직접 공개한 핵심 성분 수치**를 저장하고, 본품 용량과 단위 기준이 맞을 때만 용량당 총량을 계산한다.

이 기능이 지키는 원칙은 다음과 같다.

- 함량 미공개는 `0`이 아니다.
- 전성분 표기 순서는 정확한 `%`, `ppm`, `mg`가 아니다.
- 제품명의 `77`, `100`, `365`, `SPF50+` 같은 숫자는 함량으로 읽지 않는다.
- 식약처 사용 제한량은 규제 상한이며, 특정 제품의 실제 배합량이 아니다.
- 추출물·복합원료 함량은 그 안의 순수 활성성분 함량과 같지 않다.
- 서로 다른 유도체를 하나의 원성분 함량으로 임의 합산하지 않는다.
- 검증된 적정 함량 구간이 없는 성분은 “많을수록 좋다”로 점수화하지 않는다.

## 2. 적용한 데이터 구조

### 2.1 제품 본품 용량

`products`에 아래 필드를 추가했다.

| 필드 | 내용 |
|---|---|
| `net_content_value` | 본품 순용량. 양수만 허용 |
| `net_content_unit` | `ML` 또는 `G` |

값과 단위는 둘 다 있거나 둘 다 없어야 한다. 세트·증정품 문구를 자동 합산하지 않고, 관리자가 확인한 단품 본품 용량만 입력한다.

### 2.2 핵심 성분 표시

`product_ingredients.is_key_ingredient`로 브랜드가 강조하고 근거를 확인한 핵심 성분을 별도로 표시한다. 기존의 `concentration_note`는 자유 메모로만 남기며 수치 계산에는 사용하지 않는다.

### 2.3 구조화된 공개 함량

`product_ingredient_amount_claims`에 제품·성분별 근거 한 건을 저장한다.

| 구분 | 지원 값 |
|---|---|
| 수치 형태 | `EXACT`, `RANGE`, `MINIMUM`, `MAXIMUM` |
| 단위 | `PERCENT`, `PPM`, `PPB`, `MG_PER_G`, `MG_PER_ML` |
| 배합 기준 | `W_W`, `W_V`, `V_V`, `UNSPECIFIED` |
| 성분 기준 | `PURE_INGREDIENT`, `RAW_MATERIAL_COMPLEX`, `DERIVATIVE_EQUIVALENT` |
| 출처 | `BRAND_OFFICIAL`, `PACKAGE_LABEL`, `MFDS_FUNCTIONAL_REPORT`, `TEST_REPORT` |
| 검수 상태 | `DRAFT`, `VERIFIED`, `STALE` |

원문, 공식 URL, 페이지명, 출처에 적힌 성분명, 확인일, 검수자·검수일, 메모를 함께 보존한다. 수치는 `0`보다 커야 하며 형태별 최소·최대 값 조합을 DB와 서비스 양쪽에서 검증한다.

함량 근거는 제품-성분 연결 행과 분리된 외래 키를 사용한다. 전성분 갱신으로 성분 연결이 사라져도 근거를 삭제하지 않고 `STALE`로 바꿔 재검수 이력을 보존한다.

## 3. 용량당 환산 규칙

원문에 선언 기준이 있고 본품 단위와 물리적으로 호환될 때만 `본품 기준` 값을 만든다.

| 공개 수치 | 본품 용량 | 표시 총량 |
|---|---|---|
| `% w/w` | `g` | `용량(g) × % × 10` mg |
| `% w/v` | `mL` | `용량(mL) × % × 10` mg |
| `% v/v` | `mL` | `용량(mL) × % ÷ 100` mL |
| `ppm w/w` | `g` | `ppm × 용량(g) ÷ 1,000` mg |
| `ppm w/v` | `mL` | `ppm × 용량(mL) ÷ 1,000` mg |
| `ppb w/w` | `g` | `ppb × 용량(g) ÷ 1,000,000` mg |
| `ppb w/v` | `mL` | `ppb × 용량(mL) ÷ 1,000,000` mg |
| `mg/g` | `g` | `mg/g × 용량(g)` mg |
| `mg/mL` | `mL` | `mg/mL × 용량(mL)` mg |

다음 경우는 계산하지 않고 공개된 원문 수치만 보여준다.

- 기준이 `UNSPECIFIED`인 `%`, `ppm`, `ppb`
- `mL`를 `g`으로 바꿔야 하지만 검증된 밀도가 없는 경우
- 세트 전체 용량, 증정품, 리필을 본품과 구분할 수 없는 경우
- 복합원료 수치를 순수 활성성분 수치로 바꿔야 하는 경우

## 4. 초기 적용 데이터

브랜드 공식 제품 페이지에서 제품명·용량·성분 선언을 직접 확인할 수 있는 세 건만 `VERIFIED`로 초기 적재했다.

| 제품 | 본품 | 핵심 성분 공개 수치 | 처리 |
|---|---:|---:|---|
| 라운드랩 자작나무 수분 크림 (`birch-cream`) | 80 mL | 자작나무수액 10,000 ppm | 검증 공개 |
| 라운드랩 자작나무 수분 앰플 (`hwahae-2079267`) | 50 mL | 자작나무수액 10,000 ppm | 검증 공개 |
| 웰라쥬 리얼 히알루로닉 블루 100 앰플 (`hwahae-2153055`) | 100 mL | 하이알루로닉애씨드 0.001 ppb | 검증 공개 |

세 공식 표기는 모두 배합 기준을 별도로 명시하지 않아 `UNSPECIFIED`로 저장한다. 따라서 80 mL·50 mL·100 mL 정보는 함께 표시하지만 임의 밀도나 기준을 가정해 본품 총 mg로 바꾸지 않는다.

웰라쥬의 다른 히알루론산 계열 유도체 수치는 각각 별도 INCI이므로 `하이알루로닉애씨드 0.001 ppb`와 합산하지 않는다. 아누아 어성초 토너는 판매 지역·리뉴얼·정확 INCI 기준이 모호해 초기 검증값에서 제외했다.

공식 확인 경로:

- [Round Lab Birch Moisturizing Cream](https://roundlab.com/products/birch-moisturizing-cream)
- [Round Lab Birch Juice Moisturizing Ampoule](https://roundlab.com/products/birch-juice-ampoule)
- [Wellage Real Hyaluronic Blue 100 Ampoule](https://www.wellage.co.kr/product/detail.html?product_no=1010)

## 5. 추천 반영 방식

### 성분 화력 랭킹 v2

- 검증된 공개 함량 근거가 있으면 `amountEvidence`와 데이터 신뢰도를 높인다.
- 수치의 크기 자체는 점수에 넣지 않는다. 예를 들어 10,000 ppm이 5,000 ppm보다 무조건 좋은 것으로 계산하지 않는다.
- 공개 수치가 없을 때 전성분 순서는 낮은 비중의 처방 중심성 단서로만 사용한다.
- 공개되지 않은 제품은 `0%`나 `0점`으로 취급하지 않는다.
- 카드에는 `공개 함량`, 조건부 `본품 기준 총량`, 출처와 확인일을 표시한다.

### 개인 맞춤 추천

- 기존 피부 타입·고민 적합 점수를 유지한다.
- 검증된 함량 근거는 효능 보너스가 아니라 데이터 신뢰도와 추천 이유에 반영한다.
- 사용자에게 “공식 출처에서 어떤 성분 함량을 확인했는지”를 추천 이유로 설명한다.

향후 성분별 적정 구간을 근거 문헌과 함께 별도로 검수할 수 있게 되면 같은 INCI·같은 배합 기준끼리만 구간 점수를 추가한다. 그 전에는 높은 함량순 추천을 열지 않는다.

## 6. 관리자 운영 흐름

관리자 제품 화면에서 다음을 수행한다.

1. 제품의 본품 순용량과 단위를 입력한다.
2. 연결 성분 중 실제 핵심 성분을 체크한다.
3. 정확값·범위·이상·이하 중 공개 표기 방식을 선택한다.
4. 수치, 단위, 배합 기준, 순수 성분/복합원료/유도체 기준을 입력한다.
5. 공식 표기 원문과 HTTPS 근거 URL, 페이지명, 출처 성분명, 확인일을 입력한다.
6. `DRAFT`로 검토하거나 `VERIFIED`로 공개한다.
7. 처방 또는 연결이 바뀌면 기존 근거는 `STALE`로 남겨 다시 확인한다.

공개 API는 `VERIFIED`만 내려주며 `DRAFT`와 `STALE`은 관리자 화면에서만 확인한다.

관리 API:

- `PUT /api/v1/admin/products/{productId}/ingredients/{ingredientId}/amount`
- `DELETE /api/v1/admin/products/{productId}/ingredients/{ingredientId}/amount`

## 7. 전성분 수집 보강

공식 전성분 등록 파서를 함께 수정했다.

- `소듐하이알루로네이트(1,000ppm)`의 괄호 안 쉼표를 구분자로 오인하지 않는다.
- 별칭 매칭 때만 뒤의 정량 표기를 제외하고, 원문은 그대로 보존한다.
- 같은 표준 성분이 중복되면 자동 발행하지 않고 원문 확인을 요구한다.
- 순서 변경은 기존 연결 행을 재사용해 검증 근거를 보존한다.
- 처방에서 빠진 성분의 함량 근거는 삭제하지 않고 `STALE`로 전환한다.

## 8. 화면 적용

- 제품 상세: `핵심 성분과 공개 함량`에서 검증값, 본품 환산 가능 여부, 공식 근거를 먼저 보여준다.
- 함량 미공개 제품: `전성분 N번째 · 정확 함량 미공개`로 표시한다.
- 성분 랭킹: `함량 근거 추천순`으로 설명하고 카드에 검증 수치를 표시한다.
- 관리자: 자유 메모와 구조화된 함량 근거를 분리해 입력한다.
- 제품 기본 정보: 본품 순용량을 별도 필드로 관리한다.

## 9. 완료 기준

- [x] 미공개 함량을 0으로 저장하거나 표시하지 않는다.
- [x] 본품 용량과 공개 함량을 별도 구조로 저장한다.
- [x] 정확값·범위·최소·최대와 단위 기준을 검증한다.
- [x] 기준과 단위가 맞을 때만 본품 총량을 환산한다.
- [x] 공개 API는 검증 완료 근거만 노출한다.
- [x] 관리자만 함량 근거를 등록·수정·삭제할 수 있다.
- [x] 전성분 순서와 정확 함량 근거를 구분한다.
- [x] 적정 구간이 없는 성분은 수치가 크다는 이유로 더 추천하지 않는다.
- [x] 전성분 갱신 시 근거 이력을 삭제하지 않고 재검수 상태로 보존한다.
- [x] 괄호 안 천 단위 쉼표와 정량 표기가 있는 성분명을 처리한다.
- [x] 제품 상세·성분 랭킹·개인 맞춤 추천에 함량 근거를 연결한다.
